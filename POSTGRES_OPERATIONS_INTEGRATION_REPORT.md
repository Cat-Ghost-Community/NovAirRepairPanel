## Versioned schema and security repairs

Migration5 adds operational profile/identity protections, notification read controls and nonce history. It also closes verified financial guard gaps: a final invoice cannot be reopened as draft, draft source identity cannot be rewritten, and final payment caches/status must agree with effective obligations at commit. Employment/role/deactivation changes revoke supervisor grants in the same transaction and record a system audit; returning to a branch never resurrects an old grant. Supervisor configuration itself is not yet migrated.

Migration6 adds controlled customer merge, append-only device blacklist revocations, native internal chat and immutable chat-notification source proofs. There are **115 persisted tables**:110 canonical tables plus migration history, purchase receipt lines, notification operations, blacklist revocations and chat notification proofs. The original migration1–4 checksums remain unchanged; migration6 upgrades the migration5 device ownership guard through a narrowly proven merge exception.

The original low-stock producer function and its migration4 checksum remain unchanged. An unconditional migration6 router preserves its exact old rules and additionally permits verified current-transaction internal-message deliveries. Proof identifies message, sender, recipient, source branch and delivery branch; company conversations retain NULL source ownership while delivery uses the recipient's current branch. There is one notification inbox. Function bodies, search paths, trigger timing/events/arguments/qualifiers and proof constraints are verified. A conditional/disabled/wrong-timing trigger fails verification.

Durable operation replay now offers an explicit domain authorization hook. Chat uses it before returning cached private results: current membership, role permissions, branch, history, message/reply visibility and attachment access are rechecked. Removed members cannot retrieve old cached bodies. A changed/deleted private snapshot is rejected without rerunning the mutation. Existing financial callers retain their transaction/identity rules.

The existing chat retry helper now preserves identity across an uncertain response, including a regenerated provisional client message key. Successful confirmed operations retire the key. Upload identity binds bytes and metadata. Unicode previews use the existing shared formatter with safe character truncation and an immutable body-hashed source event, avoiding incompatible JavaScript/PostgreSQL whitespace and surrogate calculations. Read ticks use actual recipient read state.
